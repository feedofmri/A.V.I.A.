## 03 Project

### Project name
A.V.I.A. — Astronaut Health Monitoring and Decision Support

### High-level summary
A.V.I.A. is a software-only health-monitoring prototype that helps astronauts understand changing health indicators and take informed next steps during space missions. Its mission-control Cockpit and crew-focused Pulse interface combine personal baselines, visual trends, an interactive digital twin, mood check-ins and private journals. Existing local models and an optional Meta Muse assistant turn supported readings into timestamped assessments, source-linked explanations and follow-up tasks that require confirmation. Local inference and guidance work without cloud AI, while queued inputs survive connectivity interruptions.

### Project details
Long-duration spaceflight brings isolation, altered gravity, radiation exposure and limited access to immediate ground support. A.V.I.A. answers the challenge "Create Health Monitoring Software for Astronauts on Space Missions" by connecting health-indicator entry, visual self-assessment, understandable explanations and confirmed follow-up in one software workflow.

Astronauts can enter observations or import historical CSV readings. The platform compares supported vital signs with personal baselines, runs existing cardiac, stress, sleep and temporal-fusion checkpoints, and displays timestamped status, trends, alerts and missing information. Additional observations, including mood, hydration, blood pressure and temperature, remain identifiable reports rather than being presented as independently validated model measurements. A separate supplied suit checkpoint supports clearly labeled software scenarios; no physical device is needed for the demonstration.

The Cockpit gives an operator a crew overview, analytics, alerts, mission configuration and an interactive 3D body view. The digital twin lets users explore skeletal, cardiovascular, dermal and suit scenarios, with visible assumptions and baseline-versus-changed results. Bone projections are heuristic and other anatomical values include illustrative constants; the twin does not measure a person's anatomy. Pulse provides a compact crew interface for readings, symptoms, tasks and synchronization.

Behavioral Health provides reviewed and confirmed mood check-ins, a trend built from actual saved reports, sleep observations and experimental stress-model context. Crew members can write encrypted journals and explicitly share, revoke or delete entries. Operators see only shared entries. Journal sharing and permission to process a selected entry through cloud AI are separate controls.

Ten logical AI roles share an orchestration service for intake, assessment, knowledge retrieval, wellbeing, routines, actions, scenarios, briefings and supervision. Optional Meta Muse Spark explanations use authorized evidence and cited educational sources. Server validation screens unsupported claims, preserves Critical findings and requires affirmative confirmation before proposed observations or tasks are saved. Local templates remain available if cloud processing is unavailable or not consented to.

NASA Human Research Program resources inform the educational content. Supplied NASA OSDR-labelled reference tables provide experimental biological context, not live blood tests or measured astronaut bone density. The stack combines React/TypeScript and Three.js interfaces, Fastify APIs, PostgreSQL with crew-scoped access, Redis, and FastAPI/PyTorch inference. Browser outboxes preserve pending entries across interruptions; local services can run without cloud AI.

The latest full platform run passed 139 automated tests, including 22 browser workflows, with production builds and database backup/restore verification. These checks establish software behavior, not clinical accuracy. Five supplied checkpoints were retained without new training; their reference-row evaluation is disclosed, and no independent clinical validation or calibrated confidence is claimed. The fusion runtime was reconstructed from supplied artifacts, and the provider integration builds on pre-existing team integration work.

Next, we would strengthen the wellbeing role into a dedicated behavioral-health specialist, evaluate the models on permitted independent holdout data, obtain qualified clinical review, test with users and assistive technologies, improve individual longitudinal baselines, and validate deployment under realistic mission connectivity constraints. Our contribution is an inspectable, privacy-aware measurement-to-action workflow; it is an educational prototype rather than an autonomous medical decision-maker.

## 06 Use of AI and references

### Use of AI
OpenAI Codex was used for software implementation, debugging, UI development, automated-test authoring, repository review, documentation and submission-draft assistance. It worked with project source code, supplied model/adaptor files, public reference material, fictional demonstration records and test outputs.

The application optionally calls Meta's Model API using Muse Spark 1.3 (muse-spark-1.3) for structured, source-linked explanations and proposed follow-up. Its input is the user's question and scoped, authorized evidence such as readings, baselines, tasks and model outputs. Journal text is included only when its owner separately permits cloud journal processing and explicitly selects the entry. Server validation enforces permissions, screens generated output and requires confirmation before supported writes. Local guidance is available when cloud processing is disabled or unavailable.

The application also runs five supplied trained checkpoints locally: cardiac/respiratory, stress, sleep, suit-zone and temporal-fusion models. NASA biological reference context is constructed from supplied tables. These artifacts predate this implementation; no additional training or fine-tuning was performed during this development stage. Ten logical agent roles are software responsibilities, not ten separately trained models. Reference-row model evaluation and fictional live-provider regression checks do not establish clinical effectiveness or independent predictive accuracy.

This disclosure covers the AI use visible in this development record. The team should add any other AI tools used outside this record before submission.
